<objective>
Reverse the existing global-uniqueness constraint on `voters.document_number` and replace it with a duplicate-with-suffix scheme: the first voter registered with a cédula gets `duplicate_sequence = 0` ("Asignado"), every subsequent registration of the same cédula gets an incrementing sequence and `VoterStatus::DUPLICATE` ("Duplicado en disputa").

Purpose: This is the core mechanical reversal named in the phase's critical sequencing note. `docs/REGLAS_NEGOCIO.md` §2 and the migration `2026_01_19_000001_make_voter_document_number_globally_unique.php` currently document/enforce global uniqueness as an accepted, tested rule — CONTEXT.md's canonical_refs explicitly requires this to be replaced, not just patched around.
Output: `duplicate_sequence` column + composite unique index, `VoterStatus::DUPLICATE`, `VoterDuplicateAssignmentService`, rewritten `VoterTest.php` duplicate assertions, rewritten `docs/REGLAS_NEGOCIO.md` §2.
</objective>

    Create `app/Services/VoterDuplicateAssignmentService.php`:
    ```php
    namespace App\Services;

    use App\Models\Voter;
    use Illuminate\Support\Facades\DB;

    class VoterDuplicateAssignmentService
    {
        public function nextSequenceFor(string $documentNumber): int
        {
            return DB::transaction(function () use ($documentNumber) {
                $maxSequence = Voter::withTrashed()
                    ->where('document_number', $documentNumber)
                    ->lockForUpdate()
                    ->max('duplicate_sequence');

                return $maxSequence === null ? 0 : ((int) $maxSequence) + 1;
            });
        }
    }
    ```
    (The `lockForUpdate()` inside the transaction addresses Pitfall 2 — concurrent registrations of the same cédula serialize on this row lock instead of racing to compute the same next sequence.)
