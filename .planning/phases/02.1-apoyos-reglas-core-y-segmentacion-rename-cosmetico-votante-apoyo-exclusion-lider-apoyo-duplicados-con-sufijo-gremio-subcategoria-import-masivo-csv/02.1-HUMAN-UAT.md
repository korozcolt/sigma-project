## Gaps

### Gap 1: Reassignment action does not transfer ownership (`registered_by`) to a different leader/coordinator

**Source:** 02.1-VERIFICATION.md, Human Verification item 1
**Severity:** Functional gap — literal client requirement not met
**Current behavior:** `app/Filament/Resources/Voters/Pages/EditVoter.php`'s `reassignDuplicateOwner` action only changes `status` (DUPLICATE → PENDING_REVIEW) and writes a `ValidationHistory` audit row. It never touches `registered_by`, and never touches the counterpart row(s) sharing the same `document_number`.
**Required behavior:** The admin must be able to select a different leader/coordinator (from among the leaders who registered a row sharing this `document_number`) and have `registered_by` on the chosen "winning" row updated to that leader, with the existing mandatory-note + audit-trail requirements (D-03) preserved, and `duplicate_sequence` remaining immutable (D-10) — only `registered_by`/status change, never the sequence numbers.
**Affected files (likely):** `app/Filament/Resources/Voters/Pages/EditVoter.php`, `tests/Feature/ApoyoDuplicateSequenceTest.php`, possibly `app/Services/VoterDuplicateAssignmentService.php` if a helper is needed to look up sibling duplicate rows by `document_number`.
