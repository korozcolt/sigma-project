# Phase 02.1 Plan 03: Duplicate-Sequence Reversal Summary

**Reversed the global-unique(document_number) constraint into a composite unique(document_number, duplicate_sequence), added VoterStatus::DUPLICATE, and wired an Eloquent creating-hook + locked assignment service so repeated cédulas register successfully instead of throwing.**

## Performance

- **Duration:** ~25 min
- **Completed:** 2026-07-23T04:44:36Z
- **Tasks:** 3/3 completed
- **Files modified:** 7 (2 created, 5 modified)

## Accomplishments
- `voters.document_number` is no longer globally unique — a second (third, etc.) registration of the same cédula now succeeds and is tracked via an incrementing `duplicate_sequence` and `VoterStatus::DUPLICATE`.
- `VoterDuplicateAssignmentService::nextSequenceFor()` computes the next sequence under a `lockForUpdate()` transaction across `withTrashed()` rows, so numbering stays monotonic and safe under concurrent registration and soft deletes.
- All 8 pre-existing `VoterStatus` description strings renamed from "votante" to "apoyo" (D-01 cosmetic rename), alongside the new `DUPLICATE` case.
- `docs/REGLAS_NEGOCIO.md` §2 and §8 rewritten to document the new duplicate-with-suffix rule instead of the reversed global-uniqueness rule.

## Decisions Made
- Guard the `creating` hook's status-override with a value comparison (`status === null || status === VoterStatus::PENDING_REVIEW`), never `isDirty('status')`, per the plan's explicit correctness requirement — `isDirty` is always true on new unsaved models regardless of value.
- Skip sequence assignment entirely when `document_number` is blank, so `Voter::create([])` still throws the expected `Exception` from the DB's not-null constraint rather than a `TypeError` from the assignment service's typed parameter.
