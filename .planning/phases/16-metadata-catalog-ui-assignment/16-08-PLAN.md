<objective>
Close Gap 2 from `16-VERIFICATION.md`: 5 of `FilamentMetadataBulkActionTest`'s 6 tests fail deterministically (and `MetadataKeyResourceTest`'s "keeps assignment history when a key is deactivated" fails intermittently, ~1-in-4 runs) when the full `tests/Feature` suite runs in one process, even though every Metadata test passes when run in isolation.

Root cause 1: `App\Services\CampaignContext` keeps its campaign selection in private STATIC properties (`$overrideCampaignId`, `$overrideMode`) that survive across test files in the same PHP process. `FilamentMetadataBulkActionTest` only calls `Session::put('campaign_context.mode', 'all')`, which never touches those statics — so a stale `single`-mode override left by an earlier test file makes `CampaignContext::currentCampaignId()` resolve to a campaign the test's own fixtures were never attached to, `User`'s `CampaignMembershipScope` then filters the admin table down to zero rows, and the bulk action silently writes nothing with no form errors.

Root cause 2: `MetadataKeyFactory::definition()` randomizes `type` across `['numeric', 'text', 'date', 'select']` while always setting `options => null` — a `select`-typed row with no options is a shape the `MetadataKeyForm`'s `Repeater::make('options')->minItems(1)` would itself reject, so roughly 1 run in 4 the "deactivate a key" test's own fixture is already internally invalid before the test logic even runs.

Purpose: The phase's stated goal includes "test protection holds when the suite runs end to end" — this is currently false, undermining confidence in every other verified truth in `16-VERIFICATION.md`.
Output: `FilamentMetadataBulkActionTest` pins `CampaignContext` explicitly per test (matching `FilamentMetadataSectionTest`'s already-correct pattern); `MetadataKeyFactory` can no longer produce an internally-invalid select-typed row.
</objective>

```php
<?php

namespace Database\Factories;

use Illuminate\Database\Eloquent\Factories\Factory;

/**
 * @extends \Illuminate\Database\Eloquent\Factories\Factory<\App\Models\MetadataKey>
 */
class MetadataKeyFactory extends Factory
{
    public function definition(): array
    {
        return [
            'key' => fake()->unique()->slug(2, false),
            'label' => fake()->words(2, true),
            // 'select' is deliberately excluded from the random pool: the
            // MetadataKeyForm Repeater requires minItems(1) for select-typed
            // keys, so a randomly-select-typed row with options => null below
            // would be an internally-invalid catalog row. Use the dedicated
            // select() state to get a valid select-typed key with options.
            'type' => fake()->randomElement(['numeric', 'text', 'date']),
            'options' => null,
            'is_active' => true,
        ];
    }

    /**
     * Valid select-typed state: type + non-empty options together, so the row
     * never violates the form's minItems(1) constraint on the options Repeater.
     */
    public function select(): static
    {
        return $this->state(fn (array $attributes): array => [
            'type' => 'select',
            'options' => ['si', 'no'],
        ]);
    }
}
```
