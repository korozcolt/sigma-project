Create `app/Filament/Widgets/ReactIslandPocWidget.php`:
```php
<?php

declare(strict_types=1);

namespace App\Filament\Widgets;

use Filament\Widgets\ChartWidget;

/**
 * Throwaway proof-of-concept widget for Phase 20 (React Island Infrastructure).
 * Proves the wire:poll -> dispatch('updateChartData') -> Alpine bridge ->
 * React root.render() cycle works end-to-end in a real browser, across a
 * real poll tick, without ever remounting the React root. Deliberately
 * minimal per D-01 — no MonoCharts visual composition. Superseded by real
 * chart widgets starting Phase 21 (MIGR-01/MIGR-02); safe to delete once
 * this phase's infra is verified and the first real widget migrates.
 */
class ReactIslandPocWidget extends ChartWidget
{
    protected string $view = 'filament.widgets.react-chart';

    protected ?string $pollingInterval = '10s';

    protected function getType(): string
    {
        return $this->getChartKind();
    }

    protected function getChartKind(): string
    {
        return 'poc';
    }

    protected function getData(): array
    {
        $second = now()->second;

        return [
            'points' => [
                ['label' => 'A', 'value' => $second],
                ['label' => 'B', 'value' => ($second + 7) % 60],
                ['label' => 'C', 'value' => ($second + 13) % 60],
            ],
        ];
    }
}
```
Using `now()->second` guarantees the checksum-gated `dispatch('updateChartData', ...)` in the inherited `updateChartData()` actually fires on virtually every 10s poll tick (the value is different almost every tick), giving both the automated Browser test and the human checkpoint (20-03) a reliable, real signal that the poll -> dispatch -> re-render path is genuinely working, not coincidentally static.

Create `resources/views/filament/widgets/react-chart.blade.php`:
```blade
@php
    $chartId = 'react-chart-' . $this->getId();
    $pollingInterval = $this->getPollingInterval();
@endphp

<x-filament-widgets::widget>
    <x-filament::section heading="React Island PoC">
        <div @if ($pollingInterval) wire:poll.{{ $pollingInterval }}="updateChartData" @endif>
            <div
                id="{{ $chartId }}"
                wire:ignore
                x-data="reactChartBridge({
                    initialData: @js($this->getCachedData()),
                    chartKind: @js($this->getChartKind()),
                    theme: @js('light'),
                })"
                class="relative min-h-[8rem]"
            >
                <div data-react-mount class="h-full w-full"></div>

                <div
                    data-react-fallback
                    class="hidden rounded-lg border border-red-300 bg-red-50 p-4 text-sm font-medium text-red-700 dark:border-red-800 dark:bg-red-950 dark:text-red-300"
                    role="alert"
                >
                    No se pudo cargar la gráfica.
                </div>
            </div>
        </div>
    </x-filament::section>

    <script>
        (function () {
            var containerId = @js($chartId);

            window.setTimeout(function () {
                var container = document.getElementById(containerId);
                if (!container || container.dataset.reactMounted === 'true') {
                    return;
                }
                var fallback = container.querySelector('[data-react-fallback]');
                if (fallback) {
                    fallback.classList.remove('hidden');
                }
            }, 5000);
        })();
    </script>
</x-filament-widgets::widget>
```
This is deliberately named `react-chart.blade.php` (not `react-island-poc-widget.blade.php`) because ARCHITECTURE.md's recommended structure treats this as the ONE shared view every future React-backed `ChartWidget` subclass in Phase 21+ will repoint `$view` to — only `getData()`/`getChartKind()` differ per subclass. The `data-react-fallback` block covers D-03's "bundle never loaded at all" failure mode (missing Vite manifest / bad deploy) — a case `main.jsx`'s own React-level error boundary (built in 20-01) cannot cover, since if the bundle never executes there is no React code running to render anything, including an error state. The 5-second timeout checks the `data-reactMounted` marker that `main.jsx`'s `init()` sets only after a real successful mount.

<?php

use App\Enums\UserRole;
use App\Models\Campaign;
use App\Models\User;
use Database\Seeders\RoleSeeder;

beforeEach(function () {
    $this->seed(RoleSeeder::class);

it('mounts the React island PoC widget with real rendered content and refreshes it after a real wire:poll tick without remounting or console errors', function () {
    $campaign = Campaign::factory()->create(['status' => 'active']);
    $admin = User::factory()->withoutTwoFactor()->create([
        'email' => 'react-island-poc@example.com',
        'password' => 'password',
    ]);

    $page = visit(route('filament.admin.pages.dashboard'));

    $page->assertVisible('[data-testid="react-chart-poc"]');

    $firstValue = $page->script("document.querySelector('[data-testid=\"react-chart-poc-value\"]').textContent");

    // Pitfall 1's documented warning signature).
    $page->assertNoJavaScriptErrors();
});
