# Phase 21 — UI Design Contract

> Visual and interaction contract for migrating `ValidationProgressChart`, `TerritorialDistributionChart`, `SurveyResultsWidget`, and 3 embedded sparklines (`CampaignStatsOverview`, `CallCenterStatsWidget`, `SurveyStatsOverview`) from Chart.js to the Phase-20 React/Recharts island, adopting full MonoCharts visual composition (D-02) and a monochrome palette (D-03). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — deliberate, not a gap |
| Preset | not applicable |
| Component library | none (hand-built `ChartRouter.tsx` + per-kind Recharts components, per `.planning/research/ARCHITECTURE.md`) |
| Icon library | `Filament\Support\Icons\Heroicon` (existing project convention — chart widgets reuse Filament's own heading/description chrome, no new icon usage introduced by this phase) |
| Font | Manrope (already set via `AdminPanelProvider::font('Manrope')`, applies panel-wide, inherited by chart labels/tooltips) |

**Why no shadcn:** This project is a Laravel/Filament/Livewire app (`REQUIREMENTS.md` constraint: "Adopting React as the app's primary frontend framework" is explicitly out of scope). Phase 20 added a narrow, isolated React chart island — not a general React/Next/Vite application — so shadcn's component-registry model does not apply. No `components.json` exists and none should be created. All chart components are hand-built `.jsx` per `.planning/research/STACK.md` ("No TypeScript... plain `.jsx` files for the island").

## Spacing Scale

Declared values (must be multiples of 4), reused from the existing global 8-point scale — no new scale introduced for this phase:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/badge gaps inside chart header chrome |
| sm | 8px | Legend swatch gaps, tooltip internal padding |
| md | 16px | Chart card inner padding (mobile), gap between chart area and footer caption |
| lg | 24px | Chart card inner padding (desktop breakpoint), outer Filament section padding (existing `.fi-section`) |
| xl | 32px | Gap between stacked chart widgets on a dashboard (existing Filament grid gap, unchanged) |
| 2xl | 48px | Not used by this phase |
| 3xl | 64px | Not used by this phase |

**Radius exceptions (not spacing, declared separately — reused verbatim from `resources/css/filament/theme.css`, do not invent new radius values):**

| Element | Radius | Source |
|---------|--------|--------|
| Outer widget card (Filament `<x-filament::section>`) | 24px | `--radius-2xl`, already applied globally via `.fi-section` — do not add a second competing card shell inside |
| Inner chart-area container (new, MonoCharts pattern) | 14px | `--radius-lg` — matches MonoCharts' own `MonoRoundedLineChart`/`MonoRoundedStackedBarChart` chart-area radius exactly (verified against MonoCharts source) |
| Bar/column corner radius (Recharts `<Bar radius={[8, 8, 0, 0]}>`) | 8px top corners only | MonoCharts convention, verified against `MonoRoundedStackedBarChart.tsx` source ("Bar caps: 8px top and bottom corners") — SIGMA charts use top-only since bars sit on a baseline |
| Tooltip / badge pill | full (9999px) | MonoCharts convention (badge `rounded-full`) |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (legend labels, axis ticks, tooltip rows) | 14px | 400 | 1.5 |
| Label (axis tick captions, small uppercase badges) | 12px | 400 | 1.4 |
| Heading (chart title — reuses Filament's existing `.fi-section-header` style, unchanged) | 16px | 600 | 1.2 |
| Display (single large metric callout — donut center value, gauge score, sparkline latest value) | 24px | 600 | 1.15 |

Only 4 sizes, 2 weights (400 regular / 600 semibold) — no third weight. Display size is reserved for exactly one number per chart instance (the "metric display" role MonoCharts' card header uses), never for body text or multiple simultaneous values.

Numbers (tooltip values, axis ticks, metric displays) use `es-CO` locale formatting via a shared `resources/js/charts/lib/formatters.ts` helper, matching the existing `toLocaleString('es-CO')` convention already established in `resources/views/filament/components/motion-init.blade.php`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#fafafa` (zinc-50, existing `.fi-body` background) / `#ffffff` card surface | Page background, outer chart card surface |
| Secondary (30%) | `#f4f4f6` (chart-area background, matches MonoCharts' own light-theme chart-area token) + zinc-200 borders (`#e5e5e7`) | Inner chart-plot-area background, card borders, axis gridlines (`rgba(0,0,0,0.05)`) |
| Accent (10%) | `#f97316` (SIGMA's existing Filament `primary-500`, already used in `ChartCard.jsx`'s `bar` token) | Reserved for **exactly**: the single highlighted/primary data series (e.g. `ValidationProgressChart`'s "Validados" line), hover/active-point highlight, single-value emphasis elements (gauge arc fill, donut center accent), the primary-series legend swatch |
| Destructive (error state only) | Light: `#fca5a5` border / `#fef2f2` bg / `#b91c1c` text. Dark: `#991b1b` border / `#450a0a` bg / `#fca5a5` text | Reserved **exclusively** for the broken-chart error state (`ChartCard.jsx`'s `errorCard` token, already implemented in Phase 20) — never used for a data series or a legitimate zero-value state |

**Monochrome multi-series rule (D-03 — replaces the current ad hoc hex-per-series/hex-per-bar palette):** additional series/segments beyond the one accent-highlighted series do **not** get a new hue. They are rendered as opacity-layered variants of zinc-900 (light theme) / white (dark theme), following MonoCharts' verified technique:

| Layer | Opacity | Use |
|-------|---------|-----|
| Base | 100% | Primary/most-important series or largest segment |
| Mid | 50% | Secondary series |
| Top | 20% | Tertiary+ series / long-tail segments |

Concretely: `ValidationProgressChart`'s 2 series become 1 accent line ("Validados", `#f97316`) + 1 base-opacity zinc line ("Total Apoyos"), not blue+green. `TerritorialDistributionChart`'s 10-color rotation becomes a single zinc/orange ramp (top municipio = accent, remaining 9 = descending zinc opacity, not 10 distinct hues) — matches D-03's "monochrome/rounded palette" instruction and MonoCharts' own visual identity.

Accent reserved for: the single primary/highlighted series or value per chart instance, hover/active point state, gauge arc fill, donut center accent ring, primary-series legend swatch. Never applied to more than one series/segment in the same chart at once.

## Chart Visual Composition (MonoCharts Adaptation)

Applies to all 6 migrated widgets (3 `ChartWidget`s + 3 sparklines), per D-02's "full composition now" decision.

**Card shell:** reuse Filament's existing `<x-filament::section>` wrapper (24px radius, glass chrome, hover elevation, entrance animation) verbatim — do **not** build a second, competing MonoCharts-style outer card inside it. This is a deliberate divergence from MonoCharts' own outer-card styling (which assumes no host chrome exists); SIGMA's host chrome already satisfies that role.

**Inner chart-area container (new, per widget):** a `div` inside the section with 14px radius, `#f4f4f6`-equivalent (light) / near-black (dark) background, 16px padding (mobile) / 24px padding (desktop) — this is the piece MonoCharts actually contributes visually.

**Header:** existing Filament `heading`/`description` widget props stay as the chart title/subtitle — unchanged, no new header markup needed. `SurveyResultsWidget::getHeading()`'s dynamic title (question/survey name) is preserved as-is.

**Footer (optional, per widget):** a single-line 12px zinc-500 caption below the chart plot area, used only where a widget already computes a natural summary value (e.g. sparkline latest value, chart's own current total) — do not invent a footer metric that doesn't already exist in `getData()`'s output.

**Entrance animation:** Motion `initial={{ opacity: 0 }} animate={{ opacity: 1 }} transition={{ duration: 0.35, ease: [0, 0, 0.2, 1] }}` (matches SIGMA's own `--ease-decel` token) on first mount only — reuse the existing `.fi-wi:nth-child(n)` stagger delays (40ms/90ms/140ms/190ms/240ms/290ms) already defined in `theme.css` for widget-to-widget stagger; do not hand-roll new per-widget stagger values inside React.

**Tooltip:** a real positioned React tooltip component (not the browser's native `title` attribute), styled with the chart-area background token, 8px radius, 12px/14px text — mirrors MonoCharts' `DitherChartTooltipContent` pattern. Whether built via Recharts' own `<Tooltip content={...}>` custom-content prop or a small dedicated component is Claude's discretion per `21-CONTEXT.md`.

**`SurveyResultsWidget`'s dynamic kind (D-04):** the shared card shell/chart-area/header/footer chrome above applies identically regardless of whether `ChartRouter` renders `pie` or `bar` for a given render — the chrome is kind-agnostic, only the inner Recharts primitive swaps.
