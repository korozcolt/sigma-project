Confirmed by diffing: the CLI's `state advance-plan`/`update-progress` invocations produced zero on-disk change in this worktree but a real diff in the main checkout (which I reverted immediately to avoid colliding with a genuinely concurrent sibling agent session that was independently completing plan 05.1-03 directly in the main checkout at the same time).
- **Fix:** Bypassed the CLI wrapper and called the underlying `state.cjs` functions directly with `cwd: '.'` from a `node -e` one-liner run from this worktree's own directory (`cmdStateAdvancePlan`, `cmdStateRecordMetric`, `cmdStateAddDecision`, `cmdStateRecordSession`), which correctly resolved and wrote to this worktree's own `.planning/STATE.md`. For `ROADMAP.md` and `REQUIREMENTS.md`, hand-applied the same edits the CLI's `roadmap update-plan-progress`/`requirements mark-complete` commands would have made (checkbox flips, plan-progress counts, traceability table status), directly via the Edit tool.
