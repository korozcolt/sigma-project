## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `TopCoordinatorsTable`'s self-join `withCount` used the wrong column reference, always returning 0**
- **Found during:** Task 2
- **Issue:** The RESEARCH.md-suggested pattern `->join('voters', 'voters.registered_by', '=', 'users.id')` inside the `apoyos_equipo_count` constraint closure references the literal `users.id`, which Eloquent's self-relation aliasing resolves to the OUTER (coordinator) row, not the aliased leader subquery row (`laravel_reserved_N`) — so the join always matched the coordinator's own id (never a leader's), producing `apoyos_equipo_count = 0` for every coordinator regardless of their team's real apoyo count.
- **Fix:** Replaced the hardcoded `'users.id'` with `$q->qualifyColumn('id')`, which correctly resolves to the aliased leader row's id at the point the constraint closure runs (confirmed via `php artisan tinker`: `qualifyColumn('id')` returned `laravel_reserved_1.id`).
- **Files modified:** `app/Filament/Widgets/TopCoordinatorsTable.php`, `app/Exports/TopCoordinatorsExport.php`
- **Verification:** `php artisan test tests/Feature/Filament/TopCoordinatorsTableTest.php` — the 15-apoyo team-rollup assertion now passes.
- **Committed in:** `c223191` (Task 2 commit)

**2. [Rule 1 - Bug] `assertTableColumnStateSet` calls in 3 RED test files asserted against the pristine, uncounted Model instance**
- **Found during:** Task 1 (first observed in `DashboardWidgetsTest.php`'s new D-01 test), then found identically in `TopCoordinatorsTableTest.php` and `TopPollingPlacesTableTest.php`
- **Issue:** Filament's `assertTableColumnStateSet($name, $state, $record)` only calls `$this->instance()->getTableRecord($record)` (which re-resolves the row from the live table query, including any `withCount` aggregate) when `$record` is NOT already an `Illuminate\Database\Eloquent\Model`. All 3 RED test files passed the raw factory-created Model (`$leader`, `$coordinator`, `$placeA`/`$placeB`) directly, so the assertion checked the aggregate attribute (`registered_voters_count` / `apoyos_equipo_count` / `apoyos_count`) on an object that never had it loaded — always `null` — regardless of whether the underlying widget query was correct.
- **Fix:** Changed each call site to pass `->getKey()` (the record's primary key) instead of the Model instance, so Filament resolves a fresh row with aggregates merged.
- **Files modified:** `tests/Feature/DashboardWidgetsTest.php`, `tests/Feature/Filament/TopCoordinatorsTableTest.php`, `tests/Feature/Filament/TopPollingPlacesTableTest.php`
- **Verification:** All 3 test files pass in full (24 tests, 61 assertions).
- **Committed in:** `43509de` (Task 1), `c223191` (Task 2), `c4b272f` (Task 3 follow-up)

**3. [Rule 1 - Bug] `TopCoordinatorsTableTest`'s cross-campaign isolation test attached the other coordinator to the wrong campaign**
- **Found during:** Task 2
- **Issue:** `CampaignUser` (the `campaign_user` pivot model) uses the `HasCampaignContext` trait, whose `creating` hook calls `CampaignContext::enforceCampaignId()`, force-overwriting `campaign_id` with whatever the *current* `CampaignContext` session resolves to — regardless of what's passed to `attach()`. The test called `$otherCoordinator->campaigns()->attach($otherCampaign)` while the session was still pointed at `$this->campaign`, so the pivot row was silently created with `campaign_id = $this->campaign->id` instead of `$otherCampaign->id`, making the "different campaign" scenario impossible to construct and causing the coordinator to always leak into the results.
- **Fix:** Temporarily switched `Session::put('campaign_context.campaign_id', ...)` to `$otherCampaign->id` before calling `attach()`, then switched back to `$this->campaign->id` afterward — matching the established workaround pattern already used in `tests/Feature/Filament/ApoyosLideresCoordinadoresTableTest.php`.
- **Files modified:** `tests/Feature/Filament/TopCoordinatorsTableTest.php`
- **Verification:** `php artisan test tests/Feature/Filament/TopCoordinatorsTableTest.php` — isolation test now correctly asserts the other-campaign coordinator is excluded.
- **Committed in:** `c223191` (Task 2 commit)
