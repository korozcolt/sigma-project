# Phase 02.1 Plan 09: Wire Voter Resource UI (Apoyo rename, Gremio/Subcategoria, duplicate confirmation, leader exclusion) Summary

**Wired the Voter Filament resource to the D-01/D-02/D-04/D-05/D-08 building blocks from earlier waves: full Apoyo rename, cascading Gremio/Subcategoria selects, a confirm-to-proceed duplicate UX replacing the old hard-unique block, and the leader/coordinator exclusion rule.**

## Performance
- **Duration:** ~15 min
- **Tasks:** 3/3 completed
- **Files modified:** 5

## Accomplishments
- `VoterResource.php` navigation/model labels renamed to Apoyo(s); `VoterForm.php`'s last 4 remaining "votante" helperText strings renamed to "apoyo".
- Added `gremio_id`/`subcategoria_id` cascading Select pair (optional, D-04/D-05) plus optional `lugar_expedicion_cedula` and `placa` text fields to the "Información Personal" section.
- `VotersTable.php`: added `VoterStatus::DUPLICATE => 'warning'` to the status color match (previously would have thrown `UnhandledMatchError`) and a toggleable `duplicate_sequence` column.
- Replaced the `document_number` field's hard `Rule::unique(...)` block with a `DocumentNotBelongsToLeaderOrCoordinator` rule plus a soft closure that only fails when a duplicate exists AND a new `confirm_duplicate` Toggle (visible only when a duplicate is detected) is left unchecked.
- Fixed the two pre-existing Laravel Boost import-rule violations in `VoterForm.php` (`\App\Models\Voter::withTrashed()` and `\App\Services\CampaignContext::currentCampaignId()` inline namespace paths) as part of the rewrite.
- Rewrote the 3 duplicate-blocking tests in `VoterResourceTest.php` to assert the new confirm-to-proceed behavior and added a new test asserting the leader-exclusion rule fires regardless of `confirm_duplicate`.
- Removed the "(rewritten in plan 02.1-09)" placeholder note in `docs/REGLAS_NEGOCIO.md` §8.
