# Phase 05.1 Plan 02: OTP-via-Hablame-SMS for Coordinator-Creates-Leader Flow Summary

**Built the client-requested OTP verification feature end to end: a phone+campaign-scoped `otp_verifications` table/service with expiry and attempt lockout, a new `HablameSmsService::sendRaw()` method carrying Hablame's confirmed `priority:true` transactional flag, and a coordinator `create-leader` Volt form that now blocks leader-account creation until the leader's phone number is verified via a 6-digit SMS code.**

## Performance

- **Duration:** ~45 min (includes one-time worktree environment setup: git merge to sync with main, composer install, npm install/build, .env generation — required because this worktree was freshly created and several commits behind `main`, with no vendor/node_modules/.env)
- **Tasks:** 3/3
- **Files modified:** 9 (6 created, 3 modified)

## Accomplishments

- `otp_verifications` table + `OtpVerification` model store phone+campaign-scoped 6-digit codes with `expires_at`, `attempts`, and `verified_at`
- `OtpVerificationService::generate()` creates a code, persists it, and sends it via `HablameSmsService::sendRaw()` with `priority: true`, using a per-campaign message template read from `Campaign.settings['otp_message_template']` (falling back to a default `{codigo}` template)
- `OtpVerificationService::verify()` enforces expiry (10 min) and a 5-attempt lockout, using `hash_equals()` for the code comparison, independent of any authenticated session
- `HablameSmsService::sendRaw()` sends a raw, Message/Voter-independent SMS — required because OTP codes have no `Message` record at send time — without touching the existing `send()` method or its test coverage
- `resources/views/livewire/coordinator/create-leader.blade.php` now requires `sendOtp()` then a correct `verifyOtp()` before `save()` will create the leader `User`; the leader's `phone` is persisted on creation; the "Crear Líder" submit button is disabled until the phone is verified
