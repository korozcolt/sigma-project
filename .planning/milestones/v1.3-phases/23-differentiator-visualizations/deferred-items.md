## Closed by plan 23-06

- **`tests/Browser/VoterHappyPathFunnelChartTest.php`**'s `assertSee('Pendiente de Revisión')` failure (logged above under 23-03/23-05) is now fixed. Root cause was not visual clipping: recharts' `Text.js` word-wraps `LabelList position="right"` text into separate `<tspan>` lines with no space between the wrapped words, so the DOM's rendered text read `"PendientedeRevisión"` — never a substring match for `assertSee('Pendiente de Revisión')`, no matter the layout. The plan's own literal fix (reserving `margin.right=168` on `RFunnelChart` + explicit `fontSize={12}`) was applied first and rebuilt, but the failure persisted identically — confirmed by re-reading recharts' `getCartesianPosition.js`/`Funnel.js` source directly: the clamp width available to an outside-right label is a fixed *proportion* of the plot's own realWidth (set purely by the ratio between adjacent funnel-stage values), and realWidth itself shrinks as `margin.right` grows, so no margin value can reliably reserve a fixed-px label column - increasing the margin further would have made the first (widest) row's label room smaller, not bigger. Fixed for real by replacing the default `LabelList` with a custom `content` render function (`FunnelRightLabel`) that renders a plain, unclamped `<text>` at the same x/y Recharts computes for the label - a custom `content` function never receives Recharts' clamp `width` at all (confirmed in `Label.js`), so `Text.js`'s word-wrap path is bypassed entirely and the label always renders as one line with its real spacing intact. `margin.right` was reduced back down to a modest `24` (a gutter, not a label-fitting budget). Verified via 2 consecutive `php artisan test tests/Browser/VoterHappyPathFunnelChartTest.php` passes, the 2 shared `FunnelChart.jsx` consumers' tests (`CallContactabilityFunnelChartTest`, `MessageDeliveryFunnelChartTest`) still passing, and a full `tests/Browser/` suite run (23/23 passing) with zero new cross-test pollution. VIZ-06 is now genuinely closed.
