## Spacing Scale

Declared values (must be multiples of 4) — inherited verbatim from the existing chart island (Phase 20-22), confirmed via `ChartCard.jsx`/`ChartTooltip.jsx`/`StackedBarChart.jsx` Tailwind classes. No new base tokens introduced this phase.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, tooltip micro-padding (`pb-1`, `mt-1`), heatmap cell-to-cell grid gap |
| sm | 8px | Tooltip vertical padding (`py-2`), breadcrumb item gaps (treemap `nestIndexContent`), compact gaps |
| md | 16px | `ChartCard` base padding (`p-4`) — default chart canvas inset, applies to all 5 new widgets unchanged |
| lg | 24px | `ChartCard` padding at `lg:` breakpoint (`p-6`) |
| xl | 32px | Reserved — not used inside the chart island this phase |
| 2xl | 48px | Reserved — page-level widget stacking gaps (Filament's own grid, outside this contract's control) |
| 3xl | 64px | Reserved — not needed by any Phase 23 widget |

Exceptions (all phase-specific layout constraints driven directly by CONTEXT.md decisions, not new base-scale values):

- **VIZ-09 heatmap (D-14, D-15):** Outer wrapper is a bounded, dual-scroll container — `max-h-[420px] overflow-y-auto` (vertical, unbounded caller rows) combined with `overflow-x-auto` (horizontal, business-hours columns). Row height fixed at `32px` (`h-8 w-8` cells, a multiple of 4/8 — compliant), caller-name label column fixed at `140px` (not on the 8-point scale — this is a content-driven fixed sidebar width, not a spacing token, matching the existing precedent of `ChartCard`'s own fixed pixel widths for non-spacing layout dimensions). Caller-name column and hour-header row are `sticky` (`sticky left-0` / `sticky top-0`) so labels stay visible while scrolling — required for D-14's "show every caller as a row" to remain legible at scale.
- **VIZ-08 treemap (D-11):** Breadcrumb trail sits directly above the chart canvas inside the same `ChartCard` padding (no separate outer padding) — each breadcrumb segment separated by an 8px gap (`gap-2`) with a `>` separator glyph, matching `sm` token.
- **VIZ-07 Sankey:** `nodePadding={16}` (Recharts prop, matches `md` token) between stacked nodes at the same depth; `nodeWidth={12}` is a Recharts-internal rendering dimension, not a spacing token — left at the research pattern's default.
- **VIZ-02-precedent carried forward:** no unbounded-bar-count exception needed this phase (VIZ-10's stacked-area uses a fixed 4-series legend, not per-item bars).

## Typography

Declared for the React-rendered chart canvas (axis labels, tooltip, breadcrumb, empty/error state). Filament's own widget heading/description chrome (rendered by Blade, outside the React island) is governed by Filament's panel theme and out of this contract's scope — new widgets set `getHeading()`/`getDescription()` text per the Copywriting Contract below, but their rendered typography follows Filament's existing section-heading styling unchanged. Identical role/size/weight set to Phase 22 — no new typography scale introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 400 (regular) | 1.4 — axis ticks (`XAxis`/`YAxis` `tick={{fontSize: 12}}`), heatmap hour-column headers, Sankey/Treemap node text, secondary/opacity-reduced text (`text-xs opacity-60`) |
| Body | 14px | 400 (regular) | 1.5 — tooltip row text, funnel stage `LabelList` text (reused from Phase 22), heatmap caller-name row labels, breadcrumb segment text, empty-state body copy |
| Heading | 14px | 600 (semibold) | 1.3 — tooltip header row (`border-b` label), empty-state "Sin datos" heading, chart-internal emphasized values (tooltip numeric value, `font-semibold tabular-nums`), active/current breadcrumb segment |
| Display | 24px | 600 (semibold) | 1.2 — reserved (no gauge-style center stat in this phase's 5 widgets; declared for scale consistency only, not used) |

Font sizes declared: **12px, 14px, 24px** (3 distinct values across 4 roles, unchanged from Phase 22). Font weights declared: **400 (regular), 600 (semibold)** — exactly 2, no new weight introduced.

All numeric values (tooltip values, heatmap contact-rate %, axis counts) use `tabular-nums` and `formatNumber()` (`es-CO` locale, `lib/formatters.js`) — reuse directly. Heatmap contact-rate cells format as `{rate}%` (e.g. `"42.5%"`), not run through `formatNumber()` (which is integer-locale-formatted, not percent-formatted) — display the PHP-rounded `rate` value (already `round(..., 1)`) with a literal `%` suffix appended client-side.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f4f4f6` (light) / `#0f0f10` (dark) | Chart canvas background — `ChartCard.jsx`'s `chartArea` class, applies to all 5 new widgets unchanged |
| Secondary (30%) | `rgba(255,255,255,0.95)` (light) / `rgba(24,24,24,0.90)` (dark) | Tooltip surface (`ChartTooltip.jsx`, reused verbatim for the heatmap's manually-positioned tooltip per D-17), plus Filament's own panel/card chrome surrounding the chart (unchanged Filament default) |
| Accent (10%) | `#f97316` (orange, matches Filament's `primary.500`) | Reserved for exactly: (1) VIZ-06's funnel — the largest/first stage (`Pendiente de Revisión`), inherited unchanged from Phase 22's `funnel` kind, zero new frontend code; (2) VIZ-09 heatmap — the contact-rate color ramp's high end (`rgba(249,115,22, 0.12 + rate% × 0.75)`, D-13/D-16, see ramp spec below); (3) VIZ-10 stacked-area — the rank-0 series in the fixed emission order `REJECTED_CENSUS, REJECTED_OUT_OF_SCOPE, CENSUS_NOT_FOUND, CORRECTION_REQUIRED` (see Copywriting Contract note on series order) via `rankedMonochromeFill(0, 4)`, matching `StackedBarChart.jsx`'s existing per-index-not-per-value ranking convention (fixed semantic order, not re-sorted by volume — same convention VIZ-02 established). Never apply accent to more than one segment/series/stage per chart. |
| Neutral zinc ramp | `rgba(9,9,11,{opacity})` (light) / `rgba(255,255,255,{opacity})` (dark), via `rankedMonochromeFill(index, total)` | VIZ-10's remaining 3 stacked-area series (index 1-3, descending opacity); VIZ-08 treemap tiles — each rendered level's tiles filled via `rankedMonochromeFill(index, siblingCount)` computed per drill-down level (see Treemap color note below), NOT Recharts' default random `colorPanel`. |
| Sankey structural color (VIZ-07 only) | Nodes: `#111` (light) / `#fff` (dark), 4px corner radius. Links: `rgba(9,9,11,0.15)` (light) / `rgba(255,255,255,0.20)` (dark). | Deliberate departure from the accent-ranking convention — the Sankey is a structural flow diagram, not a ranked list; introducing accent on one node/link would misleadingly imply that transition is more "important" rather than merely more voluminous, which the top-N curation (D-05) already communicates via link thickness. Matches 23-RESEARCH.md Pattern 2's verified code exactly. |
| Heatmap "no data" shade (D-16) | `rgba(255,255,255,0.04)` (dark) / `rgba(9,9,11,0.03)` (light) | A caller×hour cell with zero call attempts — visually distinct (near-transparent neutral) from a real `0%`-effectiveness cell, which still renders at the ramp's minimum orange opacity (`0.12`), never fully transparent. This is the one explicit "3rd color state" this phase introduces beyond dominant/secondary/accent/destructive — required by D-16, not decorative. |
| Destructive | `#dc2626` / `border-red-300 bg-red-50 text-red-700` (light) / `border-red-800 bg-red-950 text-red-300` (dark) | `ChartCard.jsx`'s existing `errorCard` treatment — reused verbatim by all 5 new widgets for the Phase 20 D-03 explicit-error-state requirement. No destructive user actions exist in Phase 23 (read-only widgets; treemap drill-down and Sankey/heatmap hover are non-destructive navigation/inspection only), so this role is scoped to load-failure error states only. |

**Accent reserved for:** the funnel's first/largest happy-path stage (VIZ-06), the heatmap's contact-rate ramp high end (VIZ-09), and the fixed-first stacked-area series `REJECTED_CENSUS` (VIZ-10). Explicitly NOT used for: Sankey nodes/links (VIZ-07, deliberate — see Sankey structural color row above), treemap tiles (VIZ-08, uses the zinc ranked-monochrome ramp per level instead — a drilled-into level has no single "most important" tile the way a ranked list does), or any body text/border/breadcrumb chrome.

**Treemap color note (VIZ-08):** `23-RESEARCH.md` Pattern 3's example code leaves `colorPanel={undefined}`, which would fall back to Recharts' internal default (unspecified, effectively random) fill — this contract overrides that: the executor must supply a `content` render prop (or per-node `fill` in the pre-shaped tree data) that calls `rankedMonochromeFill(index, siblingCount, { isDark })` using each tile's position among its **current-level siblings** (re-ranked on every drill-down, not a single global rank), keeping the treemap visually consistent with every other ranked chart in the island (donut, stacked-bar, funnel) rather than introducing an unrelated color scheme.
