<objective>
Fix a live production 500 error: `TypeError: App\Filament\Widgets\CallQueueTable::{closure}(): Argument #1 ($query) must be of type Illuminate\Database\Eloquent\Builder, Illuminate\Database\Eloquent\Relations\HasMany given`.

Root cause: `CallQueueTable.php` line 36 eager-loads `'verificationCalls' => fn (Builder $query) => $query->latest('call_date')` inside a `->with([...])` call. For a top-level (non-dot-notation) relation constraint closure, Laravel passes the actual `Relation` subclass instance (here `HasMany`, since `CallAssignment::verificationCalls()` is a `hasMany`) — never a plain `Builder`. `HasMany` does not extend `Builder` (it proxies query-builder methods via `__call`), so PHP's strict object type-check on the closure parameter throws. This bug was always latent — it was never triggered before because every prior render of this widget had zero call-assignment rows (Eloquent skips eager-loading entirely when the base query returns no rows), so the closure was never actually invoked. It surfaced for the first time live in production/local the moment a real assignment with query results existed.
</objective>
