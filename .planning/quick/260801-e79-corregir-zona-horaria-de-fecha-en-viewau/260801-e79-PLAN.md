<objective>
Fix the audit log's displayed date/time (both the index table and the ViewAuditLog detail page) to render in America/Bogota local time (UTC-5, no DST) instead of the server's UTC timezone (`config('app.timezone')` is `'UTC'`), so the campaign team sees the actual Colombia wall-clock time an event happened.

Root cause: `TextColumn::make('created_at')->dateTime('d/m/Y H:i:s')` and `TextEntry::make('created_at')->dateTime('d/m/Y H:i:s')` both currently format the model's `created_at` (stored in UTC, standard Laravel convention) using PHP's default/app timezone with no conversion — the rendered string is the raw UTC time, 5 hours ahead of Bogota.

Purpose: The audit log (added in quick tasks 260731-n0n/nuk/o5i/odu) is actively used by super admins to trace who did what and when. A UTC-labeled-as-local timestamp is misleading for a Colombia-based campaign team reviewing "when did this actually happen."

Output: Both `AuditLogsTable.php`'s `created_at` column and `ViewAuditLog.php`'s `created_at` entry pass `'America/Bogota'` as the `dateTime()` timezone argument (Filament v4's native, built-in conversion — no manual `Carbon`/`setTimezone()` closures needed, and the stored UTC value in the DB is never touched). A regression test proves a known UTC timestamp renders as its correct Bogota-shifted (UTC-5) string.
</objective>
