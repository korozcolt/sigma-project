<objective>
Fix two display gaps on the Apoyo (Voter) view page (`app/Filament/Resources/Voters/Pages/ViewVoter.php`):

1. `latestValidationSource()`'s `match()` doesn't have a case for `validation_type = 'territory'` (written by `App\Jobs\ReconcileVoterTerritory` via `ValidationHistory::create()` whenever a voter enters/exits the campaign's territorial scope), so it falls through to `default => $latest->validation_type` and the badge shows the raw string "territory" instead of a readable Spanish label.
2. The infolist shows `polling_place_source` (badge) and `polling_place_resolved_at` (date) but never the actual resolved polling place — `Voter::pollingPlace()` (BelongsTo `PollingPlace`, `name` field) and `Voter::polling_table_number` are never rendered.

Purpose: Coordinators/reviewers viewing an Apoyo currently see a raw enum-like string for territorial reconciliations and have no way to see which specific polling place/mesa was resolved for a voter without leaving the view page.

Output: Updated `ViewVoter.php` infolist + `latestValidationSource()` match, plus Pest coverage proving both fixes render correctly.
</objective>
