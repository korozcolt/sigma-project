<objective>
Fix a 500 error on `/admin/audit-logs/{id}` (ViewAuditLog page) that occurs whenever `old_values` or `new_values` on an `AuditLog` record contains any non-array scalar element (e.g. `'id' => 32`).

Root cause: Filament's `TextEntry`, when its bound state resolves to a PHP array, treats it as a list and invokes `formatStateUsing()` once PER ARRAY ELEMENT instead of once with the whole array. The current `->formatStateUsing(fn (?array $state): string => ...)` closure on the `old_values`/`new_values` entries then receives a scalar (e.g. `int`) instead of `?array` for any non-array element, throwing a `TypeError`.

Purpose: Restore the super-admin audit log detail view (added in quick task 260731-nuk) to working order — it is currently broken for any real audit record produced by model mutations with mixed-type payloads (the common case).

Output: `ViewAuditLog.php`'s `old_values`/`new_values` entries read the model attribute directly via `->state()`, sidestepping Filament's array-as-list auto-iteration entirely. A Pest regression test proves the page returns 200 for a record with a real mixed-type payload and that the rendered response contains recognizable JSON content from those values.
</objective>
