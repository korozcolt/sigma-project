<objective>
Reduce excess 2captcha spend in production by closing two concrete gaps, both already diagnosed (no re-investigation needed):

1. `DispatchCensusRevalidation` currently has no per-run cap and no exhaustion tracking, so a voter that never resolves in the census re-enters the hourly `census:reconcile-validation` cycle forever (since `REJECTED_CENSUS` was deliberately removed as a terminal state — see `.planning/STATE.md` decision log for quick task 260730-cs3). Its sibling job, `ReconcileFallbackPollingPlaces`, already solved this exact problem with `MAX_VOTERS_PER_RUN` + `MAX_ATTEMPTS_BEFORE_EXHAUSTION` + `reconciliation_exhausted_at`. `Voter` already has both `reconciliation_attempts` and `reconciliation_exhausted_at` columns (migration `2026_07_26_120000_add_reconciliation_fields_to_voters_table.php`) — no new migration is needed, DispatchCensusRevalidation will reuse the same columns/pattern.

2. `PollingPlaceResolver::attemptLiveAutomated()`'s current backoff (`[200, 400, 800, 1200, 1600]` ms, 5 polls / 4 sleeps) gives up in ~2.6s of actual waiting, while the real Python microservice (`registraduria-service/app.py`) can take up to 150s (`for _ in range(30): sleep(5)`) to resolve a 2captcha challenge in the background. The automated cascade fires the real captcha-solving work and then abandons it almost immediately, wasting the spend across up to 3 cascading adapters per voter. Extend the polling window to ~40s (within the instructed 30-45s per-adapter bound) so the automated path has a real chance to catch `status=done` before giving up.

Purpose: Stop paying for 2captcha attempts that are immediately discarded, and stop paying for the same never-resolving voters every hour forever.
Output: Both jobs/services hardened with cap+exhaustion (job) and a realistic polling window (resolver), backed by Pest tests using fake adapters (no real 2captcha/HTTP calls).
</objective>
