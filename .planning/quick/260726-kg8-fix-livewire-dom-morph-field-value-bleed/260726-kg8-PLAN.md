<objective>
Fix a Livewire DOM-morph bug on the Registrar Apoyo (líder) and Agregar Líder (coordinador) forms: the conditional green/amber Registraduría-or-censo banner between "Número de Documento" and the following fields has no `wire:key`. Because the banner appears/disappears on every cédula blur (`updatedDocumentNumber()`), Livewire's morphdom loses stable identity for that DOM position and reshuffles the *sibling* elements that follow it — bleeding values between Nombres/Apellidos (or email/password on the coordinator form) and letting the untouched, optional Fecha de Nacimiento field pick up a stray non-date value that fails `nullable|date` validation at save time.

Purpose: Confirmed via real browser keyboard interaction (type + Tab), not just automation — this is a live-data-integrity bug affecting every apoyo/líder registered while the banner toggles.
Output: Both blade views wrap the conditional banner in a single element with a stable `wire:key`, so the wrapper is always present as the same DOM node and morphdom never has to guess whether it appeared/disappeared — sibling fields keep their own values. Regression tests added to both existing lookup test files as a safety net, explicitly documenting that full end-to-end coverage of the browser morphdom bug requires manual verification (Livewire::test() does not execute client-side DOM morphing).
</objective>
