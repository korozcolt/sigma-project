<objective>
Fix two confirmed, related bugs in the automated Registraduría polling-place lookup cascade:

1. **Cascade-by-result instead of cascade-by-availability** (`app/Services/PollingPlaceResolver.php`): `resolveAutomated()` currently advances to the next live adapter whenever `attemptLiveAutomated()` returns falsy — which happens both when an adapter is unreachable AND when a reachable adapter's already-started (already-paid-for) 2captcha query times out, errors, or comes back `waiting_captcha`. This duplicates/triplicates 2captcha spend for the same cédula. The fix: escalate to the next live adapter ONLY when `isReachable()` is false; once a reachable adapter is attempted, any non-success result stops the live cascade for that cédula and falls through to `resolveFromNationalSnapshot()` (free), never to another live adapter.

2. **`infovotantes` flow does not classify "not found"** (`registraduria-service/app.py`): unlike the `wsp` and `censo` flows, which explicitly set `outcome="not_found", data=None` when the cédula isn't found, the `infovotantes` flow always builds a 7-key dict of empty strings and marks it `status="done"` with no `outcome`. In PHP, `PollingPlaceResolver::attemptLiveAutomated()` treats any truthy array as success — a 7-key empty-string array is truthy — so a "not found" gets persisted as a genuine LIVE resolution (`registraduria_lookups` row + `voter.polling_place_source = LIVE`), corrupting data. Fixed in two layers (defense in depth): the Python flow now classifies not-found explicitly (mirrors wsp/censo), AND a PHP-side guard in `attemptLiveAutomated()` treats ANY `status=done` result with a blank `puesto_nombre` as non-success, protecting against this same class of bug from any current or future adapter.

Both diagnoses were already fully confirmed earlier in this conversation (exact file:line references below) — no re-investigation needed, only implementation.

Purpose: Stop tripling 2captcha spend per cédula on a merely-slow/failed (but reachable) live site, and stop writing "not found" as if it were a successful live resolution.
Output: `PollingPlaceResolver.php` cascade + guard hardened, `app.py` infovotantes flow corrected, full Pest coverage for both.
</objective>

```php
private function attemptLiveAutomated(LiveSourceAdapter $adapter, string $cedula): ?array
{
    if (! $adapter->isReachable()) {
        return null;
    }

    try {
        $sessionId = $adapter->startLookup($cedula);
    } catch (\Exception) {
        return null;
    }

    $backoffMs = array_fill(0, self::LIVE_POLL_ATTEMPTS, self::LIVE_POLL_INTERVAL_MS);

    foreach ($backoffMs as $i => $delayMs) {
        $result = $adapter->getResult($sessionId);

        if ($result['status'] === 'done') {
            return $result['data'];
        }

        if ($result['status'] === 'waiting_captcha' || $result['status'] === 'error') {
            return null;
        }

        if ($i < count($backoffMs) - 1) {
            Sleep::for($delayMs)->milliseconds();
        }
    }

    return null;
}
```
