# Quick Task 260731-h94: Harden registraduria-service Python microservice Summary

**Replaced Flask/Werkzeug's development server with `waitress` (single-process, 8-thread WSGI server) in `registraduria-service/app.py`, eliminating the load-dependent 503s seen during in-flight 2captcha lookups — proven via a real concurrent-load test showing 5 fast `/result/<id>` probes returning `404` in ~0.5-1.2ms each while a synthetic 10-second slow route was still sleeping on the same process.**

## Decisions Made
- waitress over gunicorn (see `key-decisions` above): the app's `sessions` dict has no external backing store, so the process model MUST stay single-process/multi-threaded; waitress is a simpler drop-in than gunicorn's `--workers 1 --threads 8 --worker-class gthread` fallback and requires zero Dockerfile change.
- `threads=8` sized around 2captcha wall-clock latency, not CPU, matching this session's earlier-diagnosed baseline.
