# Phase quick-260730-v60 Plan 01: Fix Saldos Badge Spacing With Inline Style Summary

Replaced the non-functional `ms-4` Tailwind class on the Saldos topbar dropdown with an inline `style="margin-inline-start: 1rem"` so the ~16px horizontal gap between the Saldos trigger and the adjacent "Cambiar" button actually renders.

## What Changed

- `resources/views/filament/components/saldos-badge.blade.php` line 25: swapped `class="ms-4"` for `style="margin-inline-start: 1rem"`. All other attributes (`id`, `width`, `placement`, `teleport`) unchanged. Filament's dropdown merges `$attributes` (including `style`) onto its root div, so this renders as a real `style="margin-inline-start: 1rem"` on the output `<div>`.

## Known Pre-existing Anomaly (Out of Scope)

Horizontal-margin Tailwind utilities (`ms-*`, `ml-*`, `mr-*`, `m-*`) render `0px` on computed style in the app's currently-compiled CSS bundle, even though the CSS rules are present in the served stylesheet. Vertical margin (`mt-*`) and padding (`p-*`) work fine. This is why the previous two attempts (`ms-2`, then `ms-4`) failed visually — the class never produced any margin, so the inline-style workaround was used here.

This is an environment/build issue that likely affects other horizontal-margin utilities elsewhere in the codebase. It was intentionally out of scope for this task and warrants a separate future investigation.
