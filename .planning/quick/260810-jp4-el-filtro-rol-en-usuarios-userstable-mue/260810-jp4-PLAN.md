<objective>
Fix the "Rol" filter on the Usuarios table (`UsersTable`) so it displays Spanish role labels (per `UserRole::getLabel()`) instead of the raw English Spatie role names, matching this project's "English backend, Spanish UI" convention.

Purpose: `SelectFilter::make('roles')->relationship('roles', 'name')->options(...)` is a known Filament v4 dead-code trap — when `->relationship()` is set, `SelectFilter::getFormField()` takes an entirely separate code path that ignores the manual `->options()` closure and instead plucks the raw related-model column (`roles.name`, e.g. `'area_coordinator'`) as the option label, unless `->getOptionLabelFromRecordUsing()` is also set. This has been confirmed live: a scratch Pest test dumping the filter's actual resolved `Select` options showed `4 => "area_coordinator"` (should be `4 => "Articulador"`), keyed by `roles.id` (not `roles.name` — filter values are role primary keys, confirmed by the file's existing `'can filter users by role'` test which passes `$adminRole->id`).

Output: `UsersTable.php`'s roles filter renders Spanish labels; a regression test locks in the resolved option array; confirmed (via grep — see Task 1) that no other Filament resource has the same unfixed pattern.
</objective>
