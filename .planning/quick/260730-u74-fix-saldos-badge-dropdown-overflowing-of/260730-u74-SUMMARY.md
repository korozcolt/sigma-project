# Quick Task 260730-u74: Fix saldos-badge dropdown overflowing off-screen Summary

Anchored the topbar saldos-badge dropdown to `bottom-end` with `teleport="true"`, matching Filament's native user-menu pattern, so the panel no longer overflows past the right edge of the viewport and hides the saldo values.

## What Was Done

The saldos-badge dropdown trigger sits flush against the topbar's right edge. Without an explicit `placement`, Filament's dropdown defaults to opening rightward from the trigger's left edge — pushing the panel's right edge past the viewport (128px cut off at a 1568px viewport width in the reported bug). This left the balance values (right-aligned inside the panel) invisible while the labels remained visible.

**Task 1** (commit `2a9397f`): Added `placement="bottom-end"` (anchors the panel's right edge to the trigger's right edge, opening leftward) and `teleport="true"` (moves the panel to the end of `<body>`, escaping the topbar's clipping/stacking context) to the `<x-filament::dropdown>` opening tag in `saldos-badge.blade.php`. Both values are static literals (not dynamic `:`-bound expressions) since this dropdown is always rendered in the topbar — unlike the vendor `user-menu.blade.php` this pattern was copied from, which supports two positions. No other part of the file (the `@php` data-fetching block, `id`, `width`, trigger markup, or badge/list markup) was touched.
